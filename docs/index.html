Private Tickets

A Metaplex Core event pass the door will honor only for the current owner, with a host-set resale cap and royalty enforced in Core plugins, and a check-in that turns the ticket into a “was there” souvenir.

The problem

Paper and generic NFT tickets are easy to screenshot or scalp. The host often cannot tell who actually holds the pass, cannot cap the resale price on-chain, and gets nothing when a ticket is flipped. After the door, a reused pass or a second sale of the same ticket should not be possible.

The solution

Events and the calendar stay in the app. The chain holds ownership, a host-set resale cap, a host royalty, provenance, and attendance. The door admits only the current Core asset owner. After check-in, the same NFT becomes an un-resellable souvenir.

Why it is Core-native

Core plugins do the work that used to need a heavy custom NFT stack. Attributes store door and check-in state. An Update Delegate lets a hot door key run an idempotent updatePlugin (door=1) without holding the cold authority. The grant adds the Royalties plugin so marketplaces can pay the host, AppData for the event policy and cap, and a listing path that rejects over-cap sales while ordinary transfers still work before the event. After check-in, a targeted lock turns the ticket into a souvenir — not a soulbound pass at mint.
